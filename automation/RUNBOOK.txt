10-K REDLINES: FILING UPDATE RUNBOOK
====================================

A scheduled Claude Code session follows this file each weekday evening, and
interactive sessions follow it when asked to update a dashboard. Nobody reviews
the output before it goes live: every push to main is deployed to
https://marginofdanger.github.io/10K-redlines/ by .github/workflows/deploy.yml.
The repository is public. Never write the SEC contact email (SEC_USER_AGENT)
into any file, commit message or page.

Each filing gets two analyses, in this order:
  1. the redline dashboards (this file, sections 2-6): what the company
     changed in its wording, and what that reveals;
  2. the bull/bear page (automation/BULLBEAR.txt): what the filing does to
     the investment case on fundamentals, for and against.

What the reader wants from a redline dashboard: the handful of wording
changes in a filing that reveal something management did not say outright,
each quoted exactly, before and after, labeled with how the wording moved
and how long the old wording had stood, with a sentence on why it matters.
A finding the reader could have got from the press release is not a finding.

Setup, every session:
    export SEC_USER_AGENT="<given in your prompt>"
    pip install -q beautifulsoup4 lxml


1. FIND THE WORK
----------------
    python scripts/check_new_filings.py pending --json

Each item is one of:
  annual         a new 10-K / 20-F for an existing annual dashboard
  quarterly      a new 10-Q for an existing 10-Q scanner
  build_scanner  a company with no 10-Q scanner yet (8 most recent 10-Qs listed)

Process items in the order given: updates first, oldest filing first, so
transitions chain correctly. Do at most ONE build_scanner per run. If the list
is empty, stop and report "No new filings". If every company errors with 403,
stop and report that EDGAR is rejecting requests.


2. GET THE TEXT
---------------
    python scripts/check_new_filings.py download <TICKER> --annual 2            # 10-K / 20-F
    python scripts/check_new_filings.py download <TICKER> --annual 1 --quarterly 2   # 10-Q
    python scripts/extract_sections.py companies/<t>          # or companies/<t>/10q
    python scripts/make_diffs.py companies/<t> --last 1       # or companies/<t>/10q --last 1

download names files with the dashboards' fiscal labels (fy2025, fy2027q1)
and also fetches exhibits a filer incorporates by reference (PGR's EX-13).
For a 10-Q, also download the latest 10-K: the first 10-Q after a fiscal year
end is compared against that 10-K, and make_diffs interleaves it after Q3.

extract_sections writes, per period: business, risk_factors, properties,
legal_proceedings, mda, market_risk (10-K) or mda, risk_factors,
legal_proceedings (10-Q), and for both forms:
  notes                   all notes to the financial statements
  contingencies           the commitments / contingencies note
  subsequent_events       the subsequent-events note, when there is one
  mda_liquidity           MD&A "Liquidity and Capital Resources"
  mda_critical_estimates  MD&A "Critical Accounting Estimates", when present
It prints each section's length and WARN lines. A WARN means a section is
missing or changed size more than 3x against the previous period. Open the
file and look at its first and last lines. If the boundary is wrong, fix
scripts/extract_sections.py (one generic extractor, with a small override
table for genuine quirks), re-run, and mention the fix in the commit. If the
text really did change that much (a new lawsuit, a rewritten section), that
is a finding.

Redlines list numbers-only changes (same words, new figures) separately at
the end of each file. Most are roll-forwards; scan them for a figure that
moved enough to matter.

    python scripts/sentence_signals.py companies/<t> <prev> <new> --top 80 \
        > companies/<t>/diffs/<prev>_to_<new>.signals.txt          # 10-Q: companies/<t>/10q
    python scripts/phrase_history.py companies/<t> "<phrase>"       # or --sentence "<sentence>"

sentence_signals splits every changed paragraph into sentences, aligns them,
hides roll-forwards and moves, and ranks the rest by salience with labels:
certainty (could -> have), realized (hypothetical -> actual), quant
(figures added / removed), hedge added / dropped, scope (all -> certain),
degree (significant -> substantial), condition added / dropped, named /
de-named, and how many periods the old sentence had stood unchanged.
phrase_history shows, for every downloaded 10-K and 10-Q in filing order,
where a phrase appears or the nearest version of a sentence, so "first",
"new", "no longer" and "unchanged since" can be checked. For a 10-Q, <prev>
is the previous 10-Q, or the 10-K when the 10-K came in between.

    python scripts/financials.py <TICKER> --years 3 --quarters 6

gives reported XBRL figures by period end (income statement, cash flow,
buybacks, dividends, stock comp, tax, interest, diluted shares, cash,
receivables, inventory, deferred revenue, debt, valuation allowance, purchase
obligations, guarantees) and derived ratios: free cash flow, FCF / net
income, SBC / operating cash flow, days sales outstanding, effective tax rate
and diluted share change. A "!" marks a ratio that moved sharply: find the
sentence in the filing that explains it, or note that none does. Use these
figures for every number in transition headers and reference tables. If a
figure isn't tagged, take it from the filing text and quote it.


3. ANALYZE
----------
Read, in this order:
  a. the dashboard as it stands: its tracked signals, the prior transition's
     findings and its themes. You are continuing an argument, not starting one.
  b. diffs/<prev>_to_<new>.signals.txt, top down: the ranked sentence-level
     changes with their labels. Treat "realized", "quant: removed",
     "certainty" and "de-named" labels as the strongest candidates, in that
     order.
  c. the paragraph redlines (diffs/*.redline.txt) for context, in this order:
     risk_factors, mda, mda_liquidity, notes, contingencies,
     subsequent_events, mda_critical_estimates, legal_proceedings, business.
  d. the full new section files: a sentence that did not change can matter
     because of what changed around it, and deletions read differently in
     context.

Every finding must cite its sentence pair from the signals file, or a
REMOVED / ADDED entry checked against the whole other filing. A paragraph
redline is context, not evidence: a paragraph marked REMOVED may have moved
elsewhere.

10-Q risk factors: if the section opens with a "no material changes"
incorporation and restates only some risk factors, compare each restated
paragraph with the last 10-K and the 10-Qs since (phrase_history
--sentence), never with the previous 10-Q alone. A risk factor that is
simply not restated this quarter has not been deleted.

What counts as a signal (strongest first):
  - a risk restated as having happened: "could / may X" -> "has / have
    X-ed", "we intend to" -> "we have"; or the reverse
  - commitments changing strength along the ladder may < could < likely <
    expect / intend / plan < will; weakening counts as much as firming
  - de-quantification: a figure, range or date replaced by "not material",
    a formula, or nothing; a metric disclosed one period and absent the
    next. And the reverse: a number appearing where there was none
  - guidance ranges moving, narrowing or widening; a floor or ceiling moving
    alone
  - deletions: a risk, claim, customer, product or reassurance that quietly
    stops being said; removal is often more telling than addition
  - de-naming: a product, customer, counterparty or law replaced by "a
    customer", "certain", "subscriptions"; and new named things: laws,
    regulators, lawsuits, counterparties, defined terms, facilities
  - scope and degree drift: all -> substantially all -> certain;
    significant -> substantial
  - hedges or conditions added or dropped ("currently", "at this time", "if
    at all", "subject to", "if market demand does not materialize")
  - risk-factor order: a risk moving up or down, or out of the summary
    bullets
  - one section contradicting another (MD&A optimism beside a sharpened
    risk factor; a note obligation the MD&A never mentions)
  - wording that stood unchanged for many periods and then breaks
Look for wording that firms up as hard as for wording that softens: a hedge
dropped, a risk narrowed, a figure newly disclosed are findings too.

Not signals, unless they are the story: numbers rolled forward in an
unchanged sentence, renumbered cross-references, date updates, reformatting,
boilerplate refreshed across all filers (new SEC rule language), paragraph
moves that change no meaning, and counts of hedge or modal words across a
whole section. A redline full of these is noise; say so in one line rather
than padding findings.

For each finding (one edit per finding; never bundle):
  - title: the change as a fact, with the numbers or the words that moved
    ("Backstop cap removed: 'maximum exposure of $29 billion' -> formula, no
    dollar ceiling"), not a characterization
  - tag: New / Removed / Changed / Signal
  - shift: the label(s) from the signals file, with the direction of the
    WORDING: + firmer or more disclosure, - softer or less ("quant removed
    (-)", "certainty: could -> have (+)")
  - verbatim before and after quotes in <blockquote>, labeled with the
    period; use ... to elide, never paraphrase inside quotes
  - history: from phrase_history, e.g. "'$29 billion' cap stated in Q2
    FY2026 only" or "old sentence unchanged since FY2019". Never write
    "first", "new", "no longer" or "unchanged since" without it
  - one to three sentences on why it matters, stating only what the text
    supports; if it is an inference, say so ("suggests", "consistent with")
Aim for the 6-15 findings that matter most in a transition, ranked within
each section group by importance. Fewer, sharper findings beat many.

Then do a skeptical second pass before writing the page: for each finding,
ask whether a reader who knows the company would learn something. Cut
roll-forwards, anything the quote doesn't support, and any history claim
without a phrase_history check.


4. UPDATE THE PAGE
------------------
Match the existing page exactly: copy the structure, classes and markup of
the most recent transition in the same file. Inside each finding body, put
the shift label in <p class="shift"> before the quotes and the history line
in <p class="history"> after them (add small styles for both once, from the
page's tokens, if the page has none). Add:
  - the transition header (id like the existing ones) with filing date and
    headline metrics from financials.py, then finding groups by section
  - sidebar nav link; <title>; sidebar sub-header; hero tagline and source line
    (filing count, period range, "Analysis: ... extended <Month YYYY>")
  - era card (annual dashboards)
  - a new column or row in every tracked-signal / deep-signal table that has
    one per period, and in the financial reference table
  - themes: revise each so none is stale; a theme that the new period
    contradicts must say so
Root index.html `companies` entry: endFY and signals for annual updates,
qLabel for quarterly ones, tenQ + qLabel for a new scanner.


5. VERIFY
---------
    python scripts/verify_dashboard.py companies/<t>/index.html --since origin/main

checks tag nesting, anchors, duplicate ids, table widths, that every quote
added since origin/main appears in the downloaded filing text, that every new
finding has its shift and history lines, and that the page renders in
headless Chromium with working toggles. Fix every FAIL and
re-run until it prints OK. Run it on index.html too if you changed it
(--no-render is fine there). An unmatched quote means you misquoted: fix the
quote from the section file, never loosen the check.


6. PUBLISH
----------
    python scripts/check_new_filings.py mark <TICKER> annual|quarterly <report_date> [--dashboard companies/<t>/10q/]
    git add companies/<t>/index.html companies/<t>/10q/index.html index.html automation/tracked.json scripts/
    git commit
    git pull --rebase origin main && git push origin HEAD:main

Then do the bull/bear analysis for the same filing (automation/BULLBEAR.txt)
and commit it, before moving to the next filing.

Commit message style: "feat: add Q3 2026 to META 10-Q quarterly scanner",
body = filing date, accession, period, the key signals as bullets, and a
verification line. Push after every filing so finished work goes live even
if a later one fails. If a filing can't be done to this standard, discard
its changes (git checkout -- companies/<t> index.html), leave the ledger so
the next run retries, and report why.


7. BUILD A NEW 10-Q SCANNER (build_scanner)
-------------------------------------------
Create companies/<t>/10q/index.html modeled on an existing scanner
(companies/hca/10q/ or companies/meta/10q/): same CSS, script and structure,
all content new. Download the 8 listed 10-Qs (--quarterly 8) and the 10-Ks
they interleave with (--annual 3), extract, make_diffs for all transitions.
Write every transition, 6-12 tracked signals chosen for what moves in this
company's quarterly language (each a per-quarter table), a financial
reference table from financials.py, and themes. Add tenQ and qLabel to the
root index.html entry. Verify (all quotes are new, so drop --since), mark
with --dashboard companies/<t>/10q/, commit "feat: add 10-Q quarterly scanner
for <TICKER>", push.


8. REPORT
---------
End with a short summary; for scheduled runs it becomes the phone/email
notification:
    Published: META Q3 2026 10-Q, new GOOG 10-Q scanner. Skipped: none.
    - META Q3 2026: <the most important wording change>; bull/bear: <the
      strongest bull and bear evidence, one line each>
    - GOOG scanner: <the most important pattern across 8 quarters>
plus the reason for anything skipped. If nothing was pending, say only
"No new filings".
